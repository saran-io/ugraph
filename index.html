Build verifiable knowledge
from the sources you trust.

YouTube sources & text → plain Markdown → an agent-navigable graph with citations you can check. No database. No vector store. No API key required.

Get started or install directly — uv tool install ugraph-kit 
cd ~/MyVault
ugraph init
ugraph ingest youtube https://youtube.com/@SomeChannel --limit 50
ugraph index # regenerate navigation
ugraph lint  # conformance gate — must be 0 errors
ugraph verify # every quote verbatim? every timestamp real?

Verification is the point.

A knowledge base is only worth as much as your willingness to trust it. So ugraph verify checks that every quote is a literal substring of its transcript and every timestamp is real. Everything else is plumbing.

Concepts, not summaries

Ten talks about one idea produce one concept page citing ten sources. The merge across sources is the entire value — and the hard part.

Files are the source of truth

Markdown + YAML frontmatter + relative links. You can read it, git diff it, grep it, and edit a page by hand at 2am — nothing needs re-indexing.

No model required to run

Ingesting, indexing, linting, verifying and the graph are deterministic Python. Turning transcripts into concepts is the one step that needs a model — Claude Code, an API key, or a free local Ollama model.

A ~230-page base ≈ 64 KB of JSON

Small enough to hand a model the entire graph instead of teaching it a query language.

Seven directories. That's the whole format.

A knowledge base is a folder you could have created by hand — and an agent can navigate it by following links, not by talking to a database. 

knowledge/
├── index.md          the entry point — an agent starts here and follows links
├── concepts/         ideas, synthesized across every source that taught them
├── entities/         the people, companies and tools those ideas belong to
├── sources/          one page per talk: what it covered, what it contributed
├── raw/              transcripts. Immutable. Never edited, never hand-written
├── _mocs/            hand-curated maps of content, when you want a reading order
├── SCHEMA.md         the rules, in the repo, readable by you and by an agent
└── taxonomy.json     your closed vocabulary — domains, source types, subtypes

Does the check actually catch anything? Yes.

Running ugraph verify over 385 pages found 11 defects — ten were the small ways a quote quietly stops being a quote (an editor writing "because" where the speaker said "cuz", a period the speaker never paused for), and the eleventh was a sentence nobody said, wearing quotation marks.

Every one of those was invisible to reading. That is the argument for a mechanical check: not that you are careless, but that this particular error is undetectable by care.

Build it with us.

ugraph is open source (MIT). The repo is small, the tests run in under a second, and the highest-value contribution is adding a source adapter — any adapter that writes the same two files inherits lint, verify, ledger, graph and status for free.

  1. Clone and install git clone https://github.com/saran-io/ugraph · uv venv · uv pip install -e ".[dev]"
  2. Run the tests uv run pytest & uv run ruff check src/ tests/ — under a second, no network.
  3. Pick a good first issue RSS is the most-wanted source adapter. Read CONTRIBUTING.md first — it explains the two rules worth understanding before changing anything.
  4. Open a PR CI tests on Python 3.10–3.13 and verifies both the sdist and wheel install and run.
